# Net map
Verified against: 4e34142 (2026-11-14)
Covers: Net/*.cs, Net/Bot/** (Control, Duelists, Maneuvers, Routing), MTile.Rtc/

## What this area is
Two unrelated halves that share a namespace and the `PlayerInput` record. (1) Rollback netcode: `RollbackSession`
owns one peer's input rings, snapshot ring and checksum guard over a `Simulation`; `InputCodec` is the wire form;
`NetSetup` is the transport seam Game1 sees. Transports live outside: desktop `MTile.Rtc/` (SIPSorcery) and browser
`MTile.Web/wwwroot/mtileRtc.js` (not covered). (2) Bots: `IRemoteInputSource` implementations that read the sim and
emit a raw `PlayerInput` for P2 (or P1 in bot duels). Bots never write sim state and run only offline (no rollback).
Everything here is `namespace MTile.Net` except `NetSetup` (`namespace MTile`). These player bots are NOT the enemy AI
(`Entities/Enemies/`, `EnemyController` brains, fighter league): that lives in the sim, its state (`BrainScratch`,
`Sim/ECS/Components/EcsComponents.cs:42`) is ECS and snapshotted.

## Files
Rollback core (`Net/`)
- `RollbackSession.cs` (359) - the per-peer loop: constants, `Receive`, `ProcessInbox`, `TryStep`, reconcile, checksum compare, `SendWindow`.
- `InputRing.cs` / `SnapshotRing.cs` - fixed rings keyed by absolute frame mod length; each slot stores its frame so a stale slot reads absent.
- `InputPacket.cs` - `InputPacket` (FirstFrame + Inputs[], ChecksumFrame/Checksum, AckThrough) and `InputCompare.Equal` (misprediction test).
- `InputCodec.cs` - little-endian byte layout (22-byte header + 10 bytes/input); `TryDecode` returns false on bad length.
- `NetSetup.cs` - `LocalPlayerIndex`, `Send`, and a `ConcurrentQueue` filled by `Deliver` (network thread), drained by `TryReceive` (game thread).
- `IRemoteInputSource.cs` - `Poll(Simulation, frame)`; the bot interface. `BotInputSource.cs` - seeded random walker/clicker (tests).

Bot framework (`Net/Bot/`)
- `BotView.cs` - per-frame perception record handed to maneuvers (stale target fields, `Rng`, terrain probes `Solid`/`FirstSolidAlong`) + `BotInput.Move`.
- `BotManeuver.cs` - abstract multi-frame input script: `Score`/`Begin`/`Step`/`Abort`, `Cooldown`, `OwnsLocomotion`, plus controller-facing `Category`/`Move`/`Bet`.
- `BrawlerBotInputSource.cs` - the stock brain: argmax utility selector over `DefaultManeuvers()` (order breaks ties) + chase locomotion.
- `BotDuel.cs` - `DuelBot` delegate, `Self`/`Opponent` by `selfIndex`, arenas (`hall_close`, `hall_far`, `plain_close`), `Run`, `RoundRobin`, `Brawler`.
- `BotClickRetap.cs` - struct latch re-pressing 1-frame LMB taps that did not start an action (used by Brawler and Bulldog only).
- `SpikeGuard.cs` - last-pass input filter for opposing spikes, plus `SpikeGuardConstraint` wrapper for `BotController`.
- `Control/` - `BotController.cs` (424; Move/Act selectors over behaviours, see Flow b), `BotBehaviour.cs` (`Category`, `MoveClaim`,
  `Bet`, `Stance`, `Constraint`, `Situation` buckets), `ManeuverBehaviour.cs` (adapter BotManeuver -> BotBehaviour), `MoveExecutor.cs`
  (stance target -> Move keys, `IMovePlanner` slot), `BetLedger.cs` (per-(arm,bucket) learned offsets), `BetCalibration.cs` (static prior table), `ControllerTrace.cs` (diagnostics).
- `Routing/` - `NavGrid.cs` (stand-node graph + A*; Jump/Climb/Build edges), `JumpTable.cs` + `JumpTable.g.cs` (measured jump envelopes;
  `.g.cs` generated by `MTile.Tests/Sim/ZzzRouteCalibration`), `RouteFollower.cs` (executes edges), `RouteManeuver.cs` (plans + follows),
  `RoutePlanner.cs` (`IMovePlanner` adapter putting `RouteManeuver` behind `MoveExecutor`).
- `Maneuvers/` (33 files) - shared maneuvers (incl. Ranger's `RangerBlockThrow`/`RangerCrystalWave`), one maneuver per file except `AirStabManeuvers.cs` (AirHammer, AirWhipKick). Shared helpers:
  `StabManeuver.cs`'s `StabGesture` (hold 14f + 40px swipe), `AvalancheLauncher.cs` (charge/pull/release, used by Avalanche* maneuvers),
  `BarrierPlanner.cs` (`BarrierPlanner` geometry + `BarrierLayer` one-cell-per-frame Shift+RMB placer), `BotTerrainSense.cs` (clearance).
- `Duelists/` - league bots, each with a `public static readonly DuelBot Create` field:
  `Bulldog/` (`BulldogBot` = perception + one `BotController.Step`; `BulldogManeuvers.cs` String/Grab/Stab/CrossUp/LowPoke/Breaker, plus `BulldogGuard.cs`, `BulldogPunish.cs`; `BulldogStances.cs` Chase/StepOut),
  `Harrier/` (Bulldog + `WhiffPunishManeuver`), `Ranger/` (static builder over `BulldogBot`: route planner, extra stances, `BetLedger` on),
  `Rampart/` (fort zoner, legacy selector, `RampartSense`), `Citadel/` (Rampart terrain + Bulldog melee, legacy selector),
  `Riposte/` (counter-fighter, legacy selector, `RiposteSense` + `RiposteModel` opponent tallies), `Camper/` (scripted column-stacker for routing tests; not in Game1).
  `README.md` files in Bulldog/Citadel/Rampart/Ranger/Riposte describe playstyle (prose; numbers in them are not re-verified here).

Desktop transport (`MTile.Rtc/`, separate csproj, references Core, SIPSorcery 10.0.7)
- `RtcConnection.cs` - one RTCPeerConnection + one unordered, `maxRetransmits = 0` DataChannel; non-trickle base64 SDP blobs; `OnBytes` raised off the game thread.
- `RtcSessionLink.cs` - binds an `RtcConnection` to a `RollbackSession`. Not referenced anywhere outside its own file (Desktop goes through `NetSetup`).

## Flow
(a) Rollback loop (online only; `Game1` creates it when constructed with a `NetSetup`)
1. Host wiring: `MTile.Desktop/Program.cs:41-42` sets `NetSetup.Send = rtc.Send` and `rtc.OnBytes += net.Deliver`; browser builds `NetSetup`s at `MTile.Web/Pages/Index.razor.cs:155,211,243,304` and delivers non-lobby bytes at `:376`.
2. `Game1.cs:398-401` builds `RollbackSession(_sim, LocalPlayerIndex, _ => _localInput, pkt => _net.Send(InputCodec.Encode(pkt)))`; `OnStallTimeout`/`OnDesync` only log + HUD banner (`Game1.cs:408-433`).
3. Per Update: sample `Controller.Poll` into `_localInput` (`Game1.cs:1055-1056`), drain `NetSetup.TryReceive` -> `InputCodec.TryDecode` -> `Receive` (queues into `_inbox`) (`Game1.cs:1057-1059`).
4. Wall-clock accumulator (per-Update gain capped at `MaxCatchUpSteps` = 4, `Game1.cs:147`) calls `TryStep` per whole fixed step; a false return zeroes the accumulator (`Game1.cs:1064-1075`).
5. `TryStep` -> `ProcessInbox` (`RollbackSession.cs:189`) -> `ReconcileRemote` (`:247`): ack is max'd (`:253`); inputs for unsimulated frames stored confirmed (`:260-267`);
   inputs for simulated frames within `BufferLen` flag `rollbackTo = min(frame)` when missing or `!InputCompare.Equal` (`:268-276`); older dropped (`:277`);
   checksum claims queued (`:279-280`); `_confirmedThrough` advanced while contiguous (`:285`).
6. Rollback (`:145-169`): `_sim.Restore(snap@rollbackTo)`, then for f in [rollbackTo, _frame): re-`Snapshot` into the ring, `Step(InputFor(0,f), InputFor(1,f))`, `RecordChecksum(f)`.
   If the snapshot has aged out, `MissedRollbacks++` and no correction happens (`:143-144`). Then `CheckPendingChecksums` (`:171`).
7. Stall gate (`:207-221`): if `_frame >= _confirmedThrough + InputFrameDelay + StallSlack` (3+3), re-send the window, count stalls, fire `OnStallTimeout` once at 600 consecutive, return false.
8. Predict remote for `_frame` by repeat-last if the slot is absent (`EnsurePredicted`, `:225`, `:316-320`).
9. Snapshot pre-step state into the ring at `_frame` (`:228`), `Step(p0, p1)` (`:229`), record checksum (`:230`), `_frame++`.
10. Poll local input once for sampleFrame = `_frame-1`, store it confirmed at `sampleFrame + InputFrameDelay` (`:235-239`), `SendWindow` (`:240`).
11. `SendWindow` (`:325-358`): inputs from min(peer ack + 1, newest - 7) clamped to at most 60 back, piggybacks checksum of `ConfirmedFrame` and `AckThrough = _confirmedThrough`.
12. Desync check (`:295-312`): a peer claim is compared only once `frame <= min(_confirmedThrough, _frame-1)` and our checksum slot still holds that frame; mismatch -> `DesyncCount++`, `OnDesync`.

(b) How a bot produces a PlayerInput (offline only)
1. `Game1.LoadStage` picks a bot only when `_net == null`, a second player exists and `!stage.IdleSecondary` (`Game1.cs:519-529`, by `GameConfig.BotOpponent`;
   code default Brawler, shipped `configs/game_config.json` says Ranger; seed 1234, selfIndex 0 = P2). `_botInput` is polled nowhere else (Web/Desktop/Stage/Simulation never touch bots).
2. Each fixed step: `_sim.Step(input, _botInput.Poll(_sim, _sim.Player.Frame))` (`Game1.cs:1147,1165`). `BotDuel.Run` instead passes the loop index and polls both bots before `sim.Step(ia, ib)` (`BotDuel.cs:90-94`).
3. Perception: the brain pushes the opponent's live position/action/flags into a 32-slot ring and exposes the sample `ReactionFrames` old on `BotView`
   (`BrawlerBotInputSource.cs:163-191` 6f; `BulldogBot.cs:209-245` 6f; Rampart/Citadel 8f; Riposte 7f via a 64-slot `RiposteSense.Record`, `RiposteBot.cs:237-262`). Self state and target HP are read live.
4a. Legacy selector (Brawler `:110-155`, Rampart, Citadel, Riposte): damage taken -> `Abort` active; tick cooldowns; if idle, argmax `Score` > 0 -> `Begin`;
    brain locomotion unless `OwnsLocomotion`; active `Step` (false -> cooldown); `SpikeGuard.Apply` last; Brawler then `BotClickRetap`.
4b. `BotController.Step` (Bulldog/Harrier/Ranger, `BotController.cs:123-179`): abort on damage, tick cooldowns, `Ledger.Tick`; Act selector (`:183`, Idle arm first);
    reflex selector (preempts if value > holder + PreemptGap) (`:221`); stance selection with `StanceMinHold` (`:253`); write: reflex Step, else `MoveExecutor.Drive` on the stance,
    then action Step + `MoveClaim.Mask`; constraints (SpikeGuard) last. Selection = `Value = Dealt - Lambda*Taken` (+ explore bonus), softmax over `v.Rng` when `Explore`, else argmax (`:403-423`).
5. Maneuvers write keys / LMB / RMB / Shift / cursor on `ref PlayerInput`; gestures are decoded by the sim's `InputParser` like a mouse (e.g. `StabGesture.Drive`, `StabManeuver.cs:23-28`).
6. Terrain sensing is live `Chunks.GetCellState` through `BotView.Solid` (`BotView.cs:72`), `SpikeGuard.Hostile`, `NavGrid.For` (`NavGrid.cs:86`); a running route replans once `ReplanFrames` (20) have passed and the follower is interruptible and grounded (`RouteManeuver.cs:132`).
7. Randomness: one `System.Random(seed)` per bot, shared into `BotView.Rng` (e.g. `BulldogBot.cs:105-108`); brain and maneuvers draw only from it (Slash/Stab/Burst/Eruption/Backoff/Pulse/Riposte timers, `BotController.Choose`, Bulldog's mix die).
   It is never snapshotted. No bot state is part of `SimSnapshot` or any ECS component, and none needs to survive a rollback: bots run only on the offline path (no test pairs a bot
   with `RollbackSession` either; harnesses use scripted inputs), and the stated contract is that a source is polled once per new frame and replay uses buffered inputs (`IRemoteInputSource.cs:11-14`, `RollbackSession.cs:23-24`).

## Invariants and traps
- Both peers must use the same `InputFrameDelay`: the ctor seeds frames 0..2 as confirmed default on both rings (`RollbackSession.cs:119-125`).
- The stall gate keys off `_confirmedThrough`, not `_highestRemote` (diagnostic only) (`RollbackSession.cs:60`, `:193-207`). Gating on the highest-seen frame lets a hole age out silently.
- A stalled session keeps sending (`:215`); removing that deadlocks two stalled peers.
- `SnapshotRing` holds the state at the START of a frame; replay rewrites every replayed slot (`:162`) so later rollbacks restore corrected states.
- Replay disables the static `SimTrace.Enabled` and restores it in `finally` (`:156-167`); nothing else is suppressed, so sim events fire again per replayed frame.
  Game1 routes every sim event it subscribes to (`Game1.cs:542-571`) into `PresentationEventLog`, which drops a repeat (sim frame, `PresentationId`) pair within 120 frames
  (`Presentation/PresentationEvents.cs:15-17,67-71`). A new subscriber that acts directly, or an id that is not a pure function of sim state, double-fires on rollback.
- `InputRing.InputAt` returns `default` for an absent/stale slot (`InputRing.cs:44-48`); `EnsurePredicted` leaves existing slots (confirmed or imputed) alone (`RollbackSession.cs:318`).
- `pollLocal` gets the sample frame but Game1 ignores it and returns `_localInput`, sampled once per Update (`Game1.cs:400`, `:1055-1056`). When one Update runs
  several `TryStep`s (catch-up, up to ~4), each step schedules that same input for a successive frame (`sampleFrame + 3`), i.e. the input is held across them.
- `TryStep` returning false is not an error; Game1 must drop banked time, not queue it (`Game1.cs:1069-1075`).
- `InputCodec` uses all 16 flag bits (`InputCodec.cs:27-31`, Count is a byte (`:87`)). A new `PlayerInput` button needs a wider field and an `InputCompare.Equal` term (`InputPacket.cs:41-58`); `MousePosition` (screen) is never sent or compared.
- `InputPacket.Player` is informational; `ReconcileRemote` never checks it (`RollbackSession.cs:250-281`). In the browser host, packets starting with byte 0xFE are lobby
  packets filtered before `NetSetup.Deliver` (repo-root `LobbyHello.cs:8-11`, `Index.razor.cs:376`). Same-build is enforced only there: the hello carries
  `LobbyHello.BuildId` (assembly MVID) and a mismatch fails the lobby (`Index.razor.cs:391-395,452`). The desktop host has no handshake or version check.
- Checksum compares are skipped (not counted) when our slot has aged out (`RollbackSession.cs:300,304`), so the guard can miss divergence; `MissedRollbacks` counts uncorrectable mispredictions (`:85`).
- `NetSetup.Deliver` and `RtcConnection.OnBytes` run off the game thread; only the concurrent queue may be touched there (`NetSetup.cs:20-26`, `RtcSessionLink.cs:11-15`).
- `RtcConnection.Send` silently drops while the channel is not open (`RtcConnection.cs:86-89`).
- Bots never write sim state; `v.Sim` reads are `Chunks.*`, `Coop`, `Entities` only. Maneuvers must read the target through `BotView`'s stale fields, not `v.Target`'s live fields (`BotView.cs:54-56`).
- `BotView.Frame` is the Poll frame (Game1: `Player.Frame`; BotDuel: loop index); `BotView.SelfFrame` is `Self.Frame`, the clock `CombatState` stamps use (`BotView.cs:29-31`). Do not mix them.
- `RoutePlanner.Wants` drops a running route unless its `Step` ran on frame `v.Frame - 1` (`RoutePlanner.cs:33`): a reflex/action taking Move, or a caller skipping Polls, resets routing.
- `BotController.Step` must not set the cursor: callers write `MouseWorldPosition = v.TargetPos` before stepping (`BotController.cs:37-38`, `BulldogBot.cs:172`).
- `BulldogBot` builds its controller lazily on first Poll (`BulldogBot.cs:170`); `Ledger`, `Planner`, `Disabled`, `ExtraStances`, `Calibration` set after that are ignored.
- `MoveClaim.SuspendsStance` is true for `Exclusive` and for `Forbid` covering both Left and Right (`BotBehaviour.cs:53`). Legacy `OwnsLocomotion = true` maps to `Exclusive` unless `Move` is overridden (`BotManeuver.cs:40`).
- Reflex preemption compares the candidate's corrected value to the holder's start-time bet value + `PreemptGap` (`BotController.cs:234-235`); an action holder is not re-scored (a stance's bet is re-opened each horizon, `:263-268`).
- `BetLedger.Tick` treats an HP rise (respawn) as 0 (`BetLedger.cs:143-144`); records closed before `MinRecordFrames` (8) are dropped unscored (`:129`).
- The only mutable static in the area is `JumpTable._byOffset`, a lazy cache of constant data (`JumpTable.cs:62-75`). `JumpTable.g.cs` is generated; regenerate it, do not hand-edit.
- `BotClickRetap` is a mutable struct held in a non-readonly field (`BrawlerBotInputSource.cs:107`, `BulldogBot.cs:164`); making that field `readonly` silently breaks it.

## Where to change X
- Input delay / ring size / redundancy / stall timeout: constants at `RollbackSession.cs:29-39` (both peers must match).
- Add a button to the wire: `InputCodec.PackFlags`/`UnpackFlags` (header layout comment `:14-21`) + `InputCompare.Equal`; update `MTile.Tests/Sim/InputCodecTests`.
- Desync / disconnect reaction: `OnDesync` / `OnStallTimeout` handlers in `Game1.cs:408-433`.
- New transport: implement byte send/receive and wire it to `NetSetup` the way `MTile.Desktop/Program.cs:41-42` does; nothing under `Net/` changes.
- New shared bot behaviour: a `BotManeuver` in `Net/Bot/Maneuvers/`; register in `BrawlerBotInputSource.DefaultManeuvers()` and/or a duelist's list; override `Move`/`Category`/`Bet` for controller bots.
- New positioning for controller bots: subclass `Stance` (see `BulldogStances.cs`, `RangerStances.cs`), add via `BulldogBot.ExtraStances`.
- Selection/learning knobs: `BotController` fields (`:43-68`), `BetLedger` fields (`:23-40`), priors in `BetCalibration.Field`.
- Routing: edge legality in `NavGrid.EdgesFrom` (`:142`), execution in `RouteFollower.Step`; after movement retunes rerun `ZzzRouteCalibration` to regenerate `JumpTable.g.cs`.
- Which bot plays P2 in the game: `GameConfig.BotOpponent` -> switch at `Game1.cs:520-528`.
- League/duel harness: `BotDuel.Run` / `RoundRobin`; scoring rule in `BotDuel.Result.Winner` (`BotDuel.cs:67-75`).
