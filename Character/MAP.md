# Character core map (PlayerCharacter, Movement, Sensing, Input)
Verified against: 4e34142 (2026-11-14)
Covers: Character/PlayerCharacter.cs, Character/SimFrames.cs, Character/Movement/*, Character/Sensing/*, Character/Input/*

## What this area is
The per-player frame update and everything it needs to decide how the body moves: raw `PlayerInput` -> intents, environment probes, the movement-state FSM, and the player's damage/crush/regen bookkeeping. Every file under `Character/` is `namespace MTile;` regardless of subfolder (subfolders are navigation only). All of it is sim-side and deterministic except the render-only virtuals on `MovementState` (`AnimationTag`, `AnimationProgress`, `TryAnimationGrip`, Movement.cs:120-144) and `PlayerCharacter.Sprite`/`CorrectorDebug`. Neighbours: `Character/Action/` (action FSM, `PlayerAbilityState`, `CombatState`, `ConditionState`) and `Character/Corrector/` (`AmbientCorrector`, lattice, `PathTracker`, `FoldProfile`) are reached only through the seams named in Flow and Where-to-change. Movement may not read action state; actions read movement (`ctx.CurrentMovement`). Action -> movement channels: `ctx.Modifiers` (filled at PlayerCharacter.cs:943) and `Body.AppliedForce` (`ApplyActionForces`, 972, after movement Update). Movement does read `CombatState` (an Action/ type on `PlayerAbilityState`): Grabbed/Stunned/Tumble gate on `ctx.Combat` flags (ReactionStates.cs:33,86,143), Dash on hitstun/stun/hitstop (DashState.cs:64,72,113), and every candidate on `Combat.BlockedCapabilities` (PlayerCharacter.cs:867). No file under Movement/ or Sensing/ reads the action FSM (`ActionState`/`ActionVars`/`ConditionState`); `EnvironmentContext.RecoveryIndex` reads `PreviousAction` but serves actions only.

## Flow
Entry: `Simulation.Step(input)` injects the input into the player's `Controller` (Simulation.cs:520), clears registries, publishes hurtboxes, then calls `_player.Update(_controller, ...)` (Simulation.cs:555); secondary players the same with their own controllers (563). Later in the Step: `CombatSystem.Apply` -> `PreStep` (610) -> physics. `Update` only writes `Body.AppliedForce`/velocity; physics runs after it.
`PlayerCharacter.Update` (PlayerCharacter.cs:631) per call:
1. 633-635: `_frame++` (player-local counter, restored by snapshot; intent ages and all `*Frame` stamps use it, not `Simulation._frame`), `_dt = dt`, tick spawn invuln.
2. 637-722: damage bookkeeping from LAST step's physics: wave-pin bill, crush impulse bill + slam stun (`Body.LastCrushImpulse`), sprout crush, HP regen.
3. 724-739: read `controller.Current`/`GetPrevious(1)`; number keys set `_activeBlockType`; `JumpJustPressed/UpJustPressed/DownJustPressed` written onto abilities.
4. 742-763: `Condition.Tick`, `Combat.Tick`, clear `Launched` when the launch is spent, set `Body.QuadraticDrag` from config, release the hitstop stash (`HoldingBody`).
5. 779-789: `hitstopFrozen` captured; `InputParser.Detect` issues intents into `IntentBuffer` (before any FSM runs); `_correctorScratch.BeginFrame()`.
6. 791-825: new `EnvironmentContext` (all probe caches empty); `Intent = InputIntent.From(controller)`, `Modifiers = Identity`.
7. 833-845: facing update (grounded or Grabbed only), refill `HasDoubleJumped` (grounded), `HasDashed` (grounded/WallSliding/LedgeGrab).
8. 849-857: `available = MovementResources.Available(ctx)`; if the current state's `Requires` is unmet or `CheckConditions` is false: Exit -> Enter `FallingState` (found by type in the registry).
9. 859-897: movement selection (rule below), then Exit/Enter on a switch. `ctx.CurrentMovement` set at 903.
10. 903-939: action FSM continuation + selection (Action/ internals not covered here); grabbed lock-out via `Combat.BlocksAttack`.
11. 943-958: `_currentAction.ApplyMovementModifiers` fills `ctx.Modifiers`; hitstun/slide then scales `AirAccel`/`AirDrag` and sets `PreserveExternalVelocity`.
12. 964: `_currentState.Update(ctx, ...)` writes `Body.AppliedForce`; every state ends with `ApplyAmbient`, which is where the corrector (`AmbientCorrector.Apply`, Corrector/AmbientCorrector.cs) runs. There is no separate corrector call in `Update` (the comment at 960 names `Character/AmbientCorrector.cs`; the file is `Character/Corrector/AmbientCorrector.cs`).
13. 972: `ApplyActionForces` (skipped in hitstop). 987-992: gravity-scale counter-force, `FallGravityScale` when airborne and moving down and not `SurfaceAttached`, plus `FallDrag`. 994: action `Update` (skipped in hitstop). 1007: `Meters.Step`. 1015-1023: attacker hitstop. 1025-1029: push both history rings. 1034: `_intents.Prune`.

Selection rule (PlayerCharacter.cs:874-897): iterate `_stateRegistry`; skip the current state (876), states whose `RequiredCapabilities & blockedCaps` (877), states whose `Requires` is unavailable (878), and states `PreviousState(0).Suppresses(state, ctx)` vetoes (879; `PreviousState(0)` is last frame's final state). Candidates with `CheckPreConditions` true compete on `PassivePriority` with a strict `>` (883), so the earlier-registered one wins ties. Only that single best candidate is compared: it replaces the current state iff `highestPriority > _currentState.ActivePriority` (891); equal does NOT preempt. The only bypasses are the forced drop to Falling (850-857, no priority check; selection then runs against Falling's Active 0 the same frame) and `RestoreState` (1096). There is no movement-side lookahead (that is RecoveryAction's, action FSM).

Intent path: `Controller.Current` -> `InputParser.Detect` (InputParser.cs:88) issues `Jump` (100, Space edge), `Dash` (118, Space under Shift or Shift within 3 frames after Space, not while a Shift-opened LMB press is held), `UpPress` (129), `UpHold` (141, once per press after `LedgeAutoPullHoldTime`), `PressEdge` (152), and on LMB release `Click` (<= 0.2 s hold), `Circle` (cumulative sweep >= 270 deg), or `Stab` (swipe >= 12 px); Shift-opened presses emit only `Click` (205-215). Cursor geometry is body-relative (94). Consumers `Peek`/`Consume`/`Refresh` with a per-type window; windows: jump `4/30 s`, up `6/60 s`, dash `6/60 s` (IntentBuffer.cs:121-130), default 20 frames, opener click 12. `Prune` drops consumed/aged intents (IntentBuffer.cs:193). Separately `InputIntent.From` gives `CurrentHorizontal` (this frame) and `HeldHorizontal` (same direction for 3 consecutive frames, InputIntent.cs:13).

Movement states, registration order (PlayerCharacter.cs:576-612), Passive/Active from MovementPriorities.cs. `L/R` = one instance per side.

| State | Passive/Active | Gate |
|---|---|---|
| Falling | 0/0 | fallback; always bids |
| Standing | 10/10 | Requires Legs |
| Crouched | 15/15 | Requires Legs; Down or low ceiling |
| WallSliding L/R | 20/20 | cap WallCling |
| Dropdown | 20/20 | Down + drop edge |
| TerrainCarried | 22/22 | wave-tagged volume in mass probe (support >= 0.35) or horizontal contact push > 3 px/s; no capability gate |
| Stunned | 25/25 | StunActive + ground |
| Tumble | 26/51 | `Tumbling` + airborne |
| StairClimb L/R, Parkour L/R, ArcJump L/R, Mantle L/R | 29/29 | cap LedgeGrab; held direction; all need `CorrectorClimbEnabled`, plus `StairClimbEnabled` (StairClimb) / `ParkourEnabled` (Parkour only) |
| Jumping | 30/50 | cap Jump; buffered Jump + launch source |
| RunningJump | 35/55 | cap Jump (inherits Jumping); buffered Jump + `Legs` (no corner source) + floor-relative run speed >= `RunJumpEntrySpeed`; never off stairs |
| DoubleJumping | 40/60 | cap Jump; no launch source, not `HasDoubleJumped`, Shift up |
| LedgeGrab L/R | 42/42 | cap LedgeGrab |
| LedgePull L/R | 43/43 | cap LedgeGrab |
| LedgeJump L/R | 44/55 | cap Jump; from grab/pull |
| WallJumping L/R | 45/50 | cap Jump; no ground source |
| CoveredJump | 48/52 | cap Jump; Space + L/R held, ground, ceiling gap <= 32, body past exit edge |
| Dash | 56/60 | cap Jump; chord + airborne + not `HasDashed` + not tumbling |
| Grabbed | 70/70 | `Combat.GrabbedActive` |

"cap X" = `RequiredCapabilities`. `Combat.BlockedCapabilities` (CombatState.cs:221-226): stun or grabbed blocks Jump|WallCling|LedgeGrab; hitstun alone blocks only WallCling|LedgeGrab, so jumps and Dash may ENTER in hitstun (Dash's `CheckConditions` then ends it on the next frame, DashState.cs:72), while the climb family and StairClimb (cap LedgeGrab) may not.
Registration order is Falling, Stunned, Tumble, Grabbed, Standing, Crouched, TerrainCarried, Jumping, RunningJump, DoubleJumping, WallSliding, WallJumping, CoveredJump, StairClimb, Parkour, ArcJump, Mantle, Dropdown, LedgeGrab, LedgePull, LedgeJump, Dash.

Sensing (all cached per frame in the new `EnvironmentContext`; `TryGet*` return false when absent):
- `TryGetGround` -> `GroundChecker.TryFind`: strip below the body bounds (2 px horizontal inset) of depth floatHeight (`Radius` 12) + `StandingProbeSlack` (9.8) = 21.8 px; best (highest dt-projected top) of tile tops, growing-sprout volumes, provider shapes; returns a `FloatingSurfaceDistance` (normal (0,-1), `SurfaceVelocity`, `Friction`); false if |relative vy| > `MaxGroundEngageVnRel`. `TryGetCrouchGround`: floatHeight 0, slack `ProbeSlack + FoldHoverOffset`.
- `TryGetCeiling` -> `CeilingChecker.TryFind` (20 px strip above, lowest tile bottom); `TryFindExitEdge` scans <= 8 columns. `TryGetWall(dir)` -> `WallChecker.TryFind` (12 px strip beside, 2 px vertical inset).
- `TryGetExposedCorner` -> `ExposedUpperCornerChecker.TryFind` (corner top 8..19.2 px above standing base; drop-in grab); `TryGetLedgeCorner` -> `TryFindAboveHead` (head-height line; side grab); `TryFindPullable` used directly by LedgePull. `StairChecker.TryFind` (tread/next-riser/on-flight) used directly by StairClimb.
- `GetCorridor(dir)` -> `CorridorProbe.ScanInto` (Corrector/CorridorProbe.cs), pooled scratch from PlayerCharacter.
- Channel probes: `Floor` (C-space floor via `AmbientCorrector.FloorEnvelope`, re-probed when `Body.Position` changes), `LegsInReach`, `Launching`, `Legs`, `Support(out hold)`, `HandCorner`, `Walls`, `Grip`.

## Invariants and traps
- Preemption compares the candidate's PASSIVE with the current state's ACTIVE (PlayerCharacter.cs:891). Some comments still quote old numbers (LedgeStates.cs:328 says climb passive 46; it is 29). Trust MovementPriorities.cs. Likewise PlayerCharacter.cs:862-863, Movement.cs:58, JumpStates.cs:48 and DashState.cs:41 say hitstun blocks Jump/Dash entry; per CombatState.cs:221-226 it does not (stun/grab do).
- Resource gate runs before selection and uses `available` computed once (849). A current state failing `Requires`/`CheckConditions` drops to Falling first (850-857), so a one-frame Falling->X chain is normal.
- `RequiredCapabilities` and `Suppresses` gate ENTRY only; continuation is `CheckConditions` (PlayerCharacter.cs:862-866, Movement.cs:56-60). `Suppresses` is queried on `PreviousState(0)`, so it also applies the frame after the owner exits (872).
- Hitstop freezes only `ApplyActionForces` and action `Update` (972, 994); movement selection/Update and action selection always run (765-779). The body itself is parked by `PreStep` (388-399), which Simulation calls after the update (Simulation.cs:610).
- `ctx` is rebuilt every Update and probes are cached for the whole frame (EnvironmentContext.cs:136-181). A state's `Enter` that moves the body does not invalidate `TryGetGround`/`TryGetWall`/corner caches; only `Floor` is keyed on position (224), and `Legs`/`Launching` read live velocity (246).
- `GroundChecker.ProbeSlack` is 5 px (GroundChecker.cs:8), not 20; comments claiming 20 (WallStates.cs:53-54) are stale (20 is `CeilingChecker.ProbeSlack`). The standing probe uses `StandingProbeSlack` = 5 + `BodyHeightTrim` (4.8) = 9.8; `CorrectorChannels.LegReach` derives from it.
- `Standing` and `Falling` have `CheckPreConditions` returning true; for Standing, `Requires = Legs` is the real gate (LocomotionStates.cs:47-58). `IsGrounded` is only Standing or Crouched (PlayerCharacter.cs:1037); vault/stair states are "grounded" for actions through `GroundedForActions` (Movement.cs:130, sim-affecting).
- Rollback state: `MovementVars` (flat struct, all rollback-critical fields incl. `AmbientChannelPrev`, `ManeuverChannelPrev`, `JumpHoldFrames`) + `PlayerAbilityState` clone + `InputParserState` + intents + both history rings + `_frame` + damage stamps are copied by `CaptureState` (PlayerCharacter.cs:1062) into ECS `PlayerData` (Sim/ECS/Components/EcsComponents.cs:241) and `BodyStateComp` (35; `BodyState` carries the soft contacts). Facing, `HasDoubleJumped`, `HasDashed`, `GrabbedCorner` ride in `PlayerAbilityState`. Recomputed, never snapshotted: `ctx` and its probe caches, corridor and corrector scratch, `_dt`. The controller ring is captured at sim level (Simulation.cs:783-806, `ControllerState`). New per-activation scalars go in `MovementVars`; a new field on a state instance is not snapshotted.
- State identity in snapshots is the registry INDEX (PlayerCharacter.cs:1071-1072, 1096); registry order is part of the snapshot format. `RestrictToFallAndStand` (623) shrinks the registry and is for harness stages only.
- Soft-contact refs cached on state instances (`_wall`, `_ground`, `_floor`) are rebuilt on restore by `ResetTransient` via `SoftContactOwner` tags (Movement.cs:98, 43-49; PlayerCharacter.cs:1116). Per-side flyweights (WallSliding, LedgeGrab) need distinct tags per side or replay diverges (Movement.cs:34-42).
- `MovementConfig.Current` is a get-only `[JsonIgnore]` static over `_current`, replaced wholesale by `Load` (System.Text.Json into a fresh instance, MovementConfig.cs:585): keys absent from the JSON revert to C# defaults, unknown keys are ignored, a parse exception logs and keeps the previous `Current`, a missing file logs and writes defaults back via `Save` (575-581). Only `{ get; set; }` properties load; get-only derived ones (`MaxAssistRiseSpeed`, MovementConfig.cs:47) are never read from JSON but `Save` writes them. The Update re-reads `QuadraticAirDrag` every frame (PlayerCharacter.cs:755). Hot-reload: a `FileSystemWatcher` whose `Changed` callback (thread-pool, 50 ms sleep) calls `Load` (Game1.cs:323-335), gated by `GameConfig.HotReloadMovementConfig` (default true, GameConfig.cs:155) and, since a fix made after this map's stamp, forced off whenever `Game1` has a `NetSetup` (the `_net == null` test at Game1.cs:323, repeated for the reference-clip watcher at :344). Web loads once (Game1.cs:312).
- `configs/movement_config.json:3` sets `ParkourEnabled` false while the C# default is true (MovementConfig.cs:217); it gates `ParkourState` only (ClimbStates.cs:360, checked at 68). Tests run on C# defaults: only `GroundFrictionTests` calls `Load` (a temp file, not restored) (ConfigLayoutTests.cs:115-125, parity test at 128; BACKLOG.md:209 lists the known red).
- Not in MovementConfig (hard-coded): Dash burst/duration (DashState.cs:25-36), stun/tumble air profile 0.4/0.7/1.5 (ReactionStates.cs:97-99,158-160), TerrainCarried servo constants (TerrainCarriedState.cs:59-103), crush/regen/damage constants (PlayerCharacter.cs:137-195), `JumpClearance.Headroom` 32 (JumpStates.cs:17).
- `MovementModifiers` are multiplicative scalars except `FallTerminalSpeed` (absolute px/s, +inf = off, MovementModifiers.cs:29) and the bool `PreserveExternalVelocity` (36; also set by Grabbed/Tumble and by hitstun/slide at PlayerCharacter.cs:952-958). `GravityScale` and `FallTerminalSpeed` are applied by `PlayerCharacter.Update` (987-992), not by states. `Identity` is rebuilt every frame (PlayerCharacter.cs:820).
- Forces are accelerations; Y is down, so upward pushes are negative (JumpServo.cs:20, JumpStates.cs hold forces).
- Read-only core attributes: `PlayerCharacter.Radius` 12 (16), `BodyWidthScale` 0.485 (30), `BodyHeightScale` 0.8 (31), `BodyHeightTrim` (38), `StandingHeight` pinned (57); `GroundChecker.StandingProbeSlack` and many corrector/climb constants derive from them.
- Dead or near-dead: `ExposedLowerCornerChecker`/`EnvironmentContext.TryGetExposedLowerCorner` have no sim caller (tests only). `PlayerInput.F/R/P` are sampled (Controller.cs:91-93) and have no gameplay reader anywhere in the repo; they are only carried by the netcode (Net/InputCodec.cs:44-50 pack/unpack, Net/InputPacket.cs:50-57 prediction equality, so pressing them can trigger a rollback). Controller.cs:25-28's "P toggles the eruption planner" comment is stale. `JumpServo` has one caller (LedgeStates.cs:477). `MovementConfig` JumpVelocity/JumpHoldForce/JumpInitForce drive CoveredJump phase 2 (JumpStates.cs:363,417-419), and JumpVelocity/JumpHoldForce also set the derived `MaxAssistRiseSpeed` ceiling (MovementConfig.cs:47-55) used by the climb family and `CorrectorChannels`; the ground jump itself uses `JumpPushForce`/`JumpTopSpeed` via the corrector channel.
- Order of the facing write: only grounded or Grabbed input updates `Facing` (833); wall-slide/wall-jump/double-jump/ledge/climb/stair/dash set it themselves. Movement does read `Facing` (`LedgeGrabState.FacesLip`, Dash aim), so the "Movement code doesn't read this" comment at PlayerCharacter.cs:828 is stale.

## Where to change X
- Retune a movement number: `Movement/MovementConfig.cs` default AND `configs/movement_config.json` (keep both equal; tests read defaults).
- Change which state wins: `Movement/MovementPriorities.cs` (and check registration-order ties, PlayerCharacter.cs:576-612).
- Add a movement state: new class (subclass `MovementState`), a `MovementPriorities` pair, registration in the ctor (position decides equal-Passive ties; the index is the snapshot id, so peers must run the same build), per-activation scalars in `MovementVars`, `ApplyAmbient` call on every return path of `Update`, an `AnimTag` if it needs a clip.
- Change what the body "sees": `Sensing/*Checker.cs` for one probe; `EnvironmentContext` for the cached wrapper or channel probe (`Legs`, `Support`, `Floor`).
- Change jump feel: `JumpStates.cs` (`JumpingState` channel, `HasLaunchSource`), `MovementConfig` `JumpPushForce`/`JumpTopSpeed`/`MaxJumpHoldTime`; air control in `AirControl.Apply`.
- Change input buffering/gestures/chords: `Input/InputParser.cs` (emission), windows in `Input/IntentBuffer.cs` constants, held-direction in `Input/InputIntent.cs`.
- Change crush/HP/regen/hit reaction: `PlayerCharacter.cs` Update 637-722 and `OnHit` 211-334.
- Change per-frame ordering (modifiers, gravity scale, hitstop gating): `PlayerCharacter.Update` 779-1035.
- Add something that must survive rollback: `MovementVars`, `PlayerAbilityState` (Action/), or `PlayerData` (EcsComponents.cs:241) plus `CaptureState`/`RestoreState` (1062-1117).
- Ledge/climb behaviour: `LedgeStates.cs` (hang/pull/jump), `ClimbStates.cs` (feasibility trigger in `ClimbManeuverBase.CheckPreConditions`), `StairClimbState.cs`.
